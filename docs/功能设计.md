# HTLAB 自动开釜工作站 · 软件功能设计（v1.0 原型）

本文件说明上位机软件的功能划分、工艺流程、安全联锁、数据结构，以及接入实机时需要对接的接口。
软件基于 **Electron** 开发（Windows / Linux / macOS），界面位于 `ui/`，主进程与设备网关位于 `electron/`。运行与打包方法见根目录 `README.md`。

---

## 1. 系统组成

| 编号 | 设备 | 作用 | 通讯 |
|---|---|---|---|
| ARM-01 | 六轴协作机械臂 | 样品瓶在 样品位 → 开盖 → 开塞 → 釜口 之间转运、倾倒投料 | 机械臂控制器 TCP（默认 192.168.1.20:30003） |
| CAP-01 | 开盖模块 | 底部夹紧瓶身，顶部夹爪夹住瓶盖旋转上升拧下 | PLC |
| PLG-01 | 开塞模块 | 底部夹紧，充气针刺入胶塞、充气弹出珠子锁定，电机上升拔塞 | PLC |
| RX-01 | 开釜模块 | 泄压阀泄压、压力联锁、哈夫卡箍松开、釜盖提升移开；釜体在台面下方 | PLC |
| PLC-01 | 主控 PLC | 汇总 I/O、执行模块动作、联锁硬保护 | Modbus TCP / S7 / OPC UA（默认 192.168.1.10:502） |

台面布局（与实物一致）：机械臂在左；样品托盘在前方中间；开盖、开塞两个工位并排在后方同一机架上；开釜模块在右前，釜体位于其下方柜内。

## 3. 工艺流程

流程由配方参数**自动生成**，分两条并行线：

**A 线（机械臂 · 开盖 · 开塞 · 投料）**
1. 机械臂移动至取样位 → 夹取样品瓶
2. 转运至开盖工位 → 底部夹紧、机械臂释放 → 顶部夹爪下降夹紧瓶盖 → 旋转上升拧开瓶盖（圈数、上升量取自配方）
3. 取瓶转运至开塞工位 → 底部夹紧、释放 → 充气针下降刺入 → 充气弹出珠子 → 电机上升拔塞
4. **等待 B 线开釜完成（联锁门控）**
5. 取瓶转运至釜口 → 倾倒投料（角度、时间、体积取自配方）→ 空瓶放回、机械臂回原点

**B 线（开釜，与 A 线同时开始）**
1. 读取釜内压力 / 温度
2. 打开泄压阀泄压至配方的“泄压目标压力”
3. **压力联锁校验**：釜压 < 系统“开釜安全压力上限”（默认 0.05 MPa）才解除联锁，否则报警 RX-101 并停机
4. 卡箍松开 → 釜盖提升并移开

配方关闭“开盖”或“开塞”时，对应步骤自动去掉，转运路径随之改变。

## 4. 安全联锁与权限

| 规则 | 实现位置 |
|---|---|
| 釜压 ≥ 安全上限时禁止开釜（自动校验步骤 B3、手动“卡箍松开”） | `engine.js` B3、`manualCmds().rx` |
| 卡箍未松开禁止提升釜盖；釜盖未提升到位禁止移开；釜盖未复位禁止锁紧卡箍 | `manualCmds().rx` |
| A 线投料必须等待 B 线开釜完成 | A 线“等待釜盖开启”步骤 |
| 配方泄压目标必须低于系统安全上限（保存时校验） | `Recipes.validate` |
| 自动运行期间禁止手动操作；急停状态禁止一切动作 | `Manual.run` |
| 急停解除后必须按“复位”才能再启动（可配置） | `run.js toggleEstop / needReset` |
| 未完成任务被复位 / 中止时自动保存为“中止”或“报警”记录 | `abortJob / closeRecord` |

> 软件联锁只是第二道保护，**压力联锁必须同时在 PLC 程序中硬实现**，上位机断线时 PLC 仍要拒绝松开卡箍。

角色权限：

| 功能 | 操作员 | 工程师 | 管理员 |
|---|---|---|---|
| 运行任务 / 急停 / 手动调试 | ✓ | ✓ | ✓ |
| 编辑配方 / 示教点 / 系统设置 | — | ✓ | ✓ |
| 用户管理 / 清除数据 | — | — | ✓ |

## 5. 数据结构（`ui/js/store.js`）

- `settings`：安全上限、通讯地址、仿真参数、当前用户等
- `recipes[]`：`{ id, name, version, desc, updated, params }`，`params` 字段见 `DEFAULT_RECIPE_PARAMS`
- `records[]`：`{ batch, sample, recipe, reactor, operator, start, end, duration, result, alarms, p0, pEnd, steps[], events[], pressure[[t,p]] }`
- `alarms[]`：`{ time, code, level, msg, batch, ack }`
- `users[]`、`teach`（示教点补偿）、`seq`（批次号日序号）

当前保存在本机浏览器存储中。正式版建议改为本地数据库（SQLite），只需替换 `Store.load / Store.save`。

## 6. 接入实机需要做的事

1. **设备通讯层**：增加一个后端网关（建议 Python 或 Node，运行在工控机上），负责 PLC（Modbus TCP / S7）与机械臂控制器通讯，前端通过 WebSocket 与之通讯。
2. **指令映射**：`engine.js` 中每个流程段（segment）对应一条设备指令，例如：
   - `cap.jaw → 1` ⇒ PLC 写线圈“开盖底部夹紧”，等待到位信号
   - `arm.r / arm.fy / arm.j1` 目标 ⇒ 机械臂 `movej / movel` 到对应工位点位
   - `rx.vent → 1` ⇒ 打开泄压电磁阀；`rx.p` 由压力变送器实时读回
   仿真模式下由补间动画驱动状态 `S`；实机模式下改为“下发指令 → 等待完成信号 → 用反馈刷新 `S`”，界面与 3D 无需改动。
3. **超时与故障**：每个动作需要到位超时（如泄压超时 `ventTimeout`）、扭矩超限（`capTorque`）等报警码，接入报警记录。
4. **打包**：Electron + electron-builder 已配置（three.js 已本地化，可离线运行），后续补代码签名与自动更新。
5. **示教点**：用实机示教各工位坐标，替换 `POS0` 名义坐标。
